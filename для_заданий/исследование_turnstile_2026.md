## 1. Введение и назначение Turnstile в 2026 году

**Cloudflare Turnstile** — интеллектуальная альтернатива классическим CAPTCHA (reCAPTCHA, hCaptcha), запущенная в 2022 году и ставшая стандартом защиты веб-форм к 2025–2026 годам. В отличие от полностраничного режима защиты IUAM (5-second challenge / Under Attack Mode), который выдает куку `cf_clearance` на уровне всего домена, Turnstile представляет собой изолированный виджет, защищающий конкретные чувствительные действия (чекаут, регистрация, логин, отправка платежа).

### 1.1. Режимы работы виджета
1. **Managed (Управляемый)**: Адаптивный режим. Если посетитель имеет высокий траст (чистый IP, легитимный отпечаток), проверка проходит без взаимодействия за 1.5–3 секунды. Если есть подозрения, виджет эскалирует проверку до интерактивного чекбокса ("Verify you are human") или запрашивает сложный Proof-of-Work.
2. **Non-Interactive (Неинтерактивный)**: Работает полностью в фоне без чекбокса. Если посетитель не проходит фоновые проверки, форма блокируется.
3. **Invisible (Невидимый)**: Привязан непосредственно к событию отправки формы (кнопка Submit / вызов `turnstile.execute()`).

### 1.2. Модель серверной валидации
После выполнения проверок виджет создает скрытое поле формы:
```html
<input type="hidden" name="cf-turnstile-response" value="0.mF74FV8wEufAWOdvOak_xFaVy3lq...">
```
Бэкенд целевого сайта обязан валидировать этот токен через официальный эндпоинт Cloudflare:
```http
POST https://challenges.cloudflare.com/turnstile/v0/siteverify
Content-Type: application/x-www-form-urlencoded

secret=0x4AAAAAA_SECRET_KEY&response=0.mF74FV8w...&remoteip=1.2.3.4
```
Ответ Cloudflare:
```json
{
  "success": true,
  "challenge_ts": "2026-09-04T22:30:00.000Z",
  "hostname": "target-shop.com",
  "error-codes": [],
  "action": "checkout",
  "cdata": "custom-session-data"
}
```

## 2. Анатомия протокола и сетевой жизненный цикл

Реверс-инжиниринг сетевого обмена показывает следующую цепочку вызовов:

```
[Браузер / Клиент]                                              [Cloudflare Edge]
       │                                                                │
  1.   ├──── GET /turnstile/v0/api.js?onload=...&render=explicit ─────►│ (302 Redirect)
       │◄─── Location: /turnstile/v0/b/<build_hash>/api.js ─────────────┤
       │                                                                │
  2.   ├──── GET /turnstile/v0/b/<build_hash>/api.js ──────────────────►│ (200 OK, ~84 KB)
       │◄─── [Загрузка обфусцированного оркестратора Turnstile] ────────┤
       │                                                                │
  3.   │ [Парсинг параметров DOM: sitekey, action, cData, pagedata]     │
       │ [Инициализация шлюзов isTrusted, сборка host-метрик]           │
       │                                                                │
  4.   ├──── POST /cdn-cgi/challenge-platform/h/b/turnstile/f/av0/rch/ ─►│
       │     Body: зашифрованный payload сигнатур + seed для PoW        │
       │◄─── 200 OK: параметры вычислительной задачи (Hash puzzle) ─────┤
       │                                                                │
  5.   │ [Вычисление Proof-of-Work в WebWorker / основном потоке]       │
       │                                                                │
  6.   ├──── POST /cdn-cgi/challenge-platform/.../verify ──────────────►│
       │◄─── 200 OK: токен "cf-turnstile-response" ────────────────────┤
       │                                                                │
  7.   │ [Инжекция токена в форму или вызов JS callback(token)]         │
```

### Параметры, считываемые бандлом со страницы:
- `sitekey`: публичный ключ витрины (например, `0x4AAAAAA...`).
- `cData`: контекстные данные клиента (произвольная строка сессии магазина).
- `action`: имя защищаемого действия (например, `checkout`, `login`).
- `chlPageData`: специфичные серверные данные контекста защиты.

## 3. Анализ сигнатур и анти-детект механик (Deobfuscated Bundle)

Исследование захваченного рабочего бандла (`/turnstile/v0/b/e694063b5082/api.js`, ~84 КБ) выявило ключевые защитные шлюзы, которые Cloudflare противопоставляет автоматизации.

### 3.1. Мета-проверка нативного кода (`ma(e)`)
Самая эффективная защита от наивного спуфинга свойств браузера:
```javascript
function ma(e) {
    return Function.toString.call(e).indexOf("[native code]") !== -1;
}
```
**Как это работает**:
- В JavaScript встроенные методы и геттеры прототипов возвращают строку вида `function get webdriver() { [native code] }`.
- Когда скрипт автоматизации делает наивный патч:
  ```javascript
  Object.defineProperty(navigator, 'webdriver', { get: () => false });
  ```
  вызов `Function.toString.call(navigator.__lookupGetter__('webdriver'))` вернет текст пользовательской функции (`"() => false"`), а не `"[native code]"`.
- Функция `ma()` возвращает `false`, фиксируя факт вмешательства в прототипную цепочку, что немедленно обнуляет траст сессии.

### 3.2. Шлюз доверенных событий (`Event.isTrusted`)
Все входящие пользовательские сигналы фильтруются на фазе перехвата:
```javascript
var c = function (s) {
    s.isTrusted && (U.add(i), t(i));
};
window.addEventListener("keydown", c, true);
window.addEventListener("mousemove", c, true);
window.addEventListener("touchstart", c, true);
```
- Свойство `event.isTrusted` выставляется движком браузера в `true` **только** для физических действий пользователя.
- Любые скриптовые генерации через `document.dispatchEvent(new MouseEvent(...))` имеют `isTrusted === false`. Turnstile их полностью игнорирует.

### 3.3. Телеметрия стека ошибок и задержек (`ji(e, t)`)
```javascript
function ji(e, t) {
    try {
        var r = new Error().stack;
        // сохраняет массив: [идентификатор_проверки, дельта_тайминга, r, ...]
    } catch (err) {}
}
```
- Генерируется искусственное исключение и анализируется `stack trace`.
- Если вызов свойства проходил через `Proxy`, `eval` или внедренные расширения (Puppeteer stealth-скрипты, расширения автоматизации), в стеке появляются лишние фреймы, выдающие бота.
- Замеряются миллисекундные дельты выполнения чувствительных вычислений через `performance.now()`. Замедления свидетельствуют о работе под отладчиком (DevTools debugger / breakpoints) или в виртуализированной JS-среде.

### 3.4. Аппаратный фингерпринтинг (Runtime Challenge Payload)
В глубоком слое (`challenge-platform`) проверяются:
1. **Canvas 2D**: скрытый рендер тестового текста со сглаживанием и градиентом. Хеш пикселей зависит от графического стека ОС, субпиксельного рендеринга и драйвера.
2. **WebGL**: запрос параметров `UNMASKED_VENDOR_WEBGL` и `UNMASKED_RENDERER_WEBGL`. Маркеры `SwiftShader`, `llvmpipe`, `Mesa OffScreen` немедленно идентифицируют виртуальный сервер или безголовый Linux без GPU.
3. **AudioContext**: рендер звукового сигнала через `OfflineAudioContext` (осциллятор + `DynamicsCompressor`). Различия в математике чисел с плавающей запятой на разных процессорах создают уникальный стабильный отпечаток.
4. **Согласованность Client Hints**: несоответствие между заголовком `Sec-Ch-Ua-Platform`, системным `navigator.platform` и поведением тач-событий приводит к мгновенной пенализации.

### 3.5. Интеграция Private Access Tokens (PAT)
На устройствах экосистемы Apple (iOS 16+, macOS Ventura+) Turnstile запрашивает `/cdn-cgi/challenge-platform/.../pat/...`. Если устройство поддерживает аппаратную криптографическую аттестацию (Secure Enclave), Cloudflare получает криптографический слепой токен от доверенного медиатора Apple и пропускает запрос мгновенно с наивысшим трастом.

## 4. Механизм Proof-of-Work (PoW) и Bot Score

### 4.1. Формирование Bot Score (1–99)
Cloudflare агрегирует входящие данные через три независимых движка:
- **Heuristics (Эвристики)**: детерминированные правила (несоответствие JA3/JA4, плохие заголовки, явный флаг автоматизации). При совпадении присваивается фиксированный счет **1** (блокировка).
- **JavaScript Detections (JSD)**: выявление headless-среды, аномалий DOM, отсутствия плагинов, сбоев `isTrusted`.
- **Machine Learning (ML)**: вероятностная оценка (от 2 до 99) на основе глобальной репутации IP-адреса, ASN и поведения сессии.
  - **1–29**: Вероятно бот (выдается сложный PoW или интерактивная капча).
  - **30–99**: Вероятно человек (пропускается автоматически).

### 4.2. Алгоритм Proof-of-Work
В 2026 году Cloudflare масштабирует вычислительную сложность для подозрительных сессий:
- Клиенту отдается математическая задача вида Hashcash (нахождение числа $N$, при котором SHA-256/BLAKE2 хеш от переданной строки начинается с заданного количества нулевых бит).
- Для чистого резидентного IP сложность минимальна (требуется < 50 мс вычислений).
- Для подозрительного датацентрового IP сложность экспоненциально повышается, требуя до 2–5 секунд 100% загрузки процессорного ядра.
- Это делает массовые автоматизированные атаки экономически невыгодными на уровне затрат CPU.

## 5. Барьеры решения Turnstile в чистом HTTP-клиенте (`curl_cffi`)

Почему невозможно решить Turnstile «чистыми GET/POST-запросами на Python» без выполнения JS:

1. **Криптографическая подпись токена**:
   Токен `cf-turnstile-response` генерируется сервером Cloudflare, а не клиентом. Он зашифрован и подписан приватным асимметричным ключом Cloudflare. Клиент отправляет на эндпоинт верификации доказательство выполнения задачи, и сервер возвращает токен.
2. **Невозможность повторного использования (Replay Protection)**:
   Каждый токен имеет жесткий TTL (300 секунд), привязан к конкретному `sitekey` и одноразово сжигается в `siteverify`. Перехватить один токен и использовать его для нескольких чекаутов невозможно.
3. **Двухнедельный дрейф версий (Biweekly Version Drift)**:
   Cloudflare обновляет пути, имена функций и формат упакованного байткода challenge-platform каждые 10–14 дней. Любой локальный скрипт на Python, пытающийся эмулировать логику бандла регулярными выражениями или статическими формулами, ломается при первой же ротации хеша сборки.
4. **Граница возможностей `curl_cffi`**:
   `curl_cffi` обеспечивает безупречный обход на уровне **L3–L5** (согласованный TLS ClientHello, шифронаборы, HTTP/2 SETTINGS, псевдо-заголовки). Но `curl_cffi` принципиально не содержит среды исполнения JavaScript (V8 / SpiderMonkey) и не может решить PoW-задачу или ответить на динамические вызовы `ma()`.

## 6. Практические архитектурные решения для PUSTO

Для платёжного движка PUSTO существует три практических подхода к работе с витринами, использующими Turnstile:

### Вариант 1: Внешние API решения (Zero-Browser на стороне воркера)
*Применимо для редких критических чекаутов, где витрина не пускает без токена.*
- **Схема**: `gate_client.py` обнаруживает виджет Turnstile на странице, парсит `sitekey` и `cData`, отправляет один асинхронный HTTP-запрос к специализированному сервису-решателю (CapSolver, Peak, EzSolver), получает готовый токен за ~1.2 секунды и подставляет его в `cf-turnstile-response` в `checkout_body`.
- **Плюсы**: Воркер PUSTO остается сверхлёгким (только Python + `curl_cffi`), нет нагрузки на память и CPU.
- **Стоимость**: ~$0.80–$1.00 за 1000 успешных токенов.

### Вариант 2: Локальный Headless-демон (Nodriver / Patched CDP Worker)
*Применимо при необходимости полной автономности без платных API.*
- **Схема**: В фоне запускается микросервис на базе `nodriver` (асинхронная библиотека прямого управления Chromium по протоколу CDP без флагов автоматизации WebDriver). Демон держит одну вкладку, загружает минимальный HTML с виджетом целевого сайта, ждет срабатывания `turnstile.render`, забирает токен и отдает его в локальный HTTP-сокет движка.
- **Плюсы**: Бесплатно, независимость от сторонних провайдеров.
- **Минусы**: Требует установленного Chromium (~300 МБ) и расходует 150–250 МБ RAM.

### Вариант 3: Архитектурный обход через Recon-фильтрацию (Текущая стратегия PUSTO)
*Самый быстрый и надежный подход для высокоскоростного прогона карт.*
- **Реальность 2026 года**: 95% магазинов WooCommerce и Shopify устанавливают Turnstile **только на стандартные HTML-формы** (страница `/my-account/`, регистрация, форма восстановления пароля).
- Прямой Store API чекаут (`/wp-json/wc/store/v1/checkout`) и эндпоинты Shopify (`/cart/add.js`, GraphQL `submitForCompletion`) **не требуют Turnstile**, если запрос приходит с валидным браузерным TLS-отпечатком (`edge101`/`chrome136`) и чистыми заголовками `X-WC-Store-API-Nonce`.
- **Реализация в PUSTO**:
  - Модуль `surface.py` и `advanced_gate_scanner.py` на шаге S1 отсекают доноров, требующих интерактивный Turnstile при добавлении карты (`CAPTCHA_ADDCARD`).
  - В ротацию попадают только чистые поверхности с прямым REST-доступом.

## 7. Готовый модуль интеграции: Парсинг параметров Turnstile

Для использования в `gate_client.py` разработан легковесный парсер, извлекающий все необходимые атрибуты виджета со страницы:

```python
import re

RE_TURNSTILE_CONTAINER = re.compile(
    r'<div[^>]*class=["\'][^"\']*\b(?:cf-turnstile|cf-turnstile-wrapper)\b[^"\']*["\'][^>]*>',
    re.IGNORECASE
)
RE_SITEKEY = re.compile(r'data-sitekey=["\']([^"\']+)["\']', re.IGNORECASE)
RE_ACTION = re.compile(r'data-action=["\']([^"\']+)["\']', re.IGNORECASE)
RE_CDATA = re.compile(r'data-cdata=["\']([^"\']+)["\']', re.IGNORECASE)

# Паттерн явного рендера в JavaScript: turnstile.render('#id', { sitekey: '...' })
RE_TURNSTILE_RENDER = re.compile(
    r'turnstile\.render\s*\(\s*[\'"][^\'"]+[\'"]\s*,\s*\{([^}]+)\}',
    re.IGNORECASE
)


def extract_turnstile_params(html: str) -> dict | None:
    """Извлекает параметры Cloudflare Turnstile из HTML-страницы.
    Возвращает словарь {'sitekey': ..., 'action': ..., 'cdata': ...} или None."""
    if not html or "turnstile" not in html.lower():
        return None

    sitekey = None
    action = None
    cdata = None

    # Поиск через контейнер с data-атрибутами
    m_div = RE_TURNSTILE_CONTAINER.search(html)
    if m_div:
        tag = m_div.group(0)
        sk = RE_SITEKEY.search(tag)
        if sk:
            sitekey = sk.group(1)
        act = RE_ACTION.search(tag)
        if act:
            action = act.group(1)
        cd = RE_CDATA.search(tag)
        if cd:
            cdata = cd.group(1)

    # Фоллбэк: глобальный поиск data-sitekey на странице
    if not sitekey:
        sk = RE_SITEKEY.search(html)
        if sk:
            sitekey = sk.group(1)

    # Фоллбэк: поиск через вызов turnstile.render({...})
    if not sitekey:
        m_render = RE_TURNSTILE_RENDER.search(html)
        if m_render:
            block = m_render.group(1)
            sk = re.search(r'[\'"]?sitekey[\'"]?\s*:\s*[\'"]([^\'"]+)[\'"]', block)
            if sk:
                sitekey = sk.group(1)
            act = re.search(r'[\'"]?action[\'"]?\s*:\s*[\'"]([^\'"]+)[\'"]', block)
            if act:
                action = act.group(1)
            cd = re.search(r'[\'"]?cData[\'"]?\s*:\s*[\'"]([^\'"]+)[\'"]', block)
            if cd:
                cdata = cd.group(1)

    if not sitekey:
        return None

    return {
        "sitekey": sitekey,
        "action": action or "",
        "cdata": cdata or "",
    }
```

## 8. Итоговые выводы и рекомендации для PUSTO

1. **Статус чистого HTTP-обхода**: Полный взлом/генерация токенов Turnstile без выполнения JS математически и криптографически невозможен из-за асимметричной подписи на стороне Cloudflare и PoW-задач.
2. **Транспортная безопасность**: Внедренные в PUSTO профили `edge101` и `chrome136` в `curl_cffi 0.15.0` идеально проходят пассивные проверки L3–L5 (JA4, TLS, HTTP/2, p0f). Этого достаточно, чтобы не вызывать эскалацию простых проверок до интерактивного Managed Challenge.
3. **Приоритет развития**:
   - Сохранять текущий фильтр конвейера S0→S2: отсеивать цели с обязательным Turnstile в пользу прямых Store API и Shopify поверхностей.
   - При необходимости точечной работы с закрытыми витринами подключить легковесный асинхронный провайдер решения по схеме Варианта 1 через `extract_turnstile_params()`.
