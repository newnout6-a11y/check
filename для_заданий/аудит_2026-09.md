## Найденное

### AUD-001 [P3] config.py — пул IMPERSONATIONS: 21 профиль, README заявляет 22
Фактический подсчёт по кортежу IMPERSONATIONS (config.py:21-32):
Chromium 6 (136/142/145/146/133a/131_android) + Safari 7 (184/184_ios/260/260_ios/18_0/17_2_ios/17_0)
+ Firefox 4 (147/144/135/133) + Edge/Tor 3 (101/99/145) + fallback chrome116 = **21**.
README §8: «Пул из 22 актуальных профилей». Расхождение документации с кодом на единицу.

### AUD-002 [P2] pusto_logger.py:log_verdict — консольная индикация расходится с таксономией хитов
`log_verdict` (pusto_logger.py:~268): `is_hit = "APPROVED" in verdict or "3DS" in verdict`.
Любой `3DS_*` (включая 3DS_REQUIRED и 3DS_REDIRECT) рисуется зелёным фоном BG_GREEN как хит.
По config.HIT_VERDICTS 3DS-вердикты хитами не являются (бот расширяет только до
3DS_FRICTIONLESS/3DS_CHALLENGE). Оператор в консоли видит «хит» там, где статистика его не
засчитает. Визуальная дезинформация, влияет на ручную оценку прогонов.

### AUD-003 [P3] pusto_logger.py:log_gate — цветовая ветка для WARN/DEBUG одноцветна
Второй стиль вызова (gate, msg, level): `WARN` и `DEBUG` оба падают в BRIGHT_CYAN —
жёлтая подсветка WARN не реализована, хотя INFO жёлтый. Косметика, но WARN теряет визуальный вес.

### AUD-004 [P2] config.py — CHROME_IMPERSONATE дублирует источник истины
`CHROME_IMPERSONATE = "edge101"` помечен комментарием «устарело: см. pick_impersonate()»,
но остаётся отдельной константой, которую читает surface._FALLBACK_IMP (по README). Два места
правды об отпечатке: пул IMPERSONATIONS и одиночная константа. При следующей чистке пула
edge101 может вылететь из одного места и остаться в другом.

### AUD-005 [P3] bin_cache.py — допущение «BIN не меняется со временем»
TTL ∞ заложен в дизайн. Банковские BIN-диапазоны переносятся/сливаются (особенно prepaid-эмитенты
США из пула bin_steering: MetaBank/Pathward, Green Dot, Sutton). Кэш может годами держать
устаревший тип карты. Для скорости — верно, для точности steering-решений — риск тихого дрейфа.
Кандидат на TTL 90-180 дней при следующем рефакторинге.

### AUD-006 [P3] bin_cache.py:_ensure — молчаливое глотание всех исключений
`except Exception: pass` на создании схемы. Задокументировано («кэш — ускоритель»), но при
недоступной data/ кэш отключается без единой строки в логе — регресс ловится только по
нулевому размеру bin_cache.db. Дёшево исправимо логом в pusto_logger, отмечено как наблюдение.

### AUD-007 [P1] gate_client.store_api_confirm — технические статусы вне таксономии → UNKNOWN вместо ERROR
store_api_confirm (gate_client.py:~1500-1900) возвращает статусы: `GUEST_CHECKOUT_DISABLED`,
`CAPTCHA_CHECKOUT`, `NO_PM_SLUG`, `PM_SLUG_MISSING`, `NO_PRODUCT_UNDER_CAP`, `NO_PRODUCTS`,
`ADD_ITEM_NO_JSON`, `VARIATION_REQUIRED`. Ни один не входит в config.VERDICTS.
bot/main.py:913 прогоняет их через engine_cfg.coerce_verdict → все сводятся к **UNKNOWN**
(не ERROR). Последствия в run_gate (bot/main.py:918-925):
1. кредит НЕ возвращается (refund только на ERROR) — пользователь платит за мёртвый магазин;
2. фолл-троу к следующему гейту не срабатывает (break только при verdict == "ERROR");
3. статистика мусорится UNKNOWN.
По смыслу это сбои движка/цели, а не свойство карты.

### AUD-008 [P1] SESSION_EXPIRED / SESSION_CANCELED — в движке есть, в таксономии нет
Фиксация №7 добавила терминальные статусы в classify_pi_verdict (gate_client.py:~810-815),
но в config.VERDICTS (24 класса) они НЕ внесены. README §7 заявляет «сверено с кодом» —
нет: движок генерирует вердикты, которых таксономия не знает. Через coerce_verdict в боте
они становятся UNKNOWN → кредит сгорает, сессия числится «неизвестной». Двойное
рассогласование: код ↔ таксономия ↔ документация.

### AUD-009 [P2] gate_client.stripe_3ds2_authenticate — timeZoneOffset захардкожен -120 (Европа)
browser-объект 3DS2 (gate_client.py:~728): `"timeZoneOffset": -120` — UTC+2. При US-карте
с US-биллингом (GEO_POOLS US) и en-US локалью браузер живёт в европейской таймзоне —
классический антифрод-мISMATCH (гео биллинга vs гео устройства). Рабочий файл фиксации №6
заявляет «точный расчет browserTZ под страну карты» для frictionless_engine — в gate_client
этого нет. Модули расходятся: hit_gate через gate_client шлёт -120 всегда.

### AUD-010 [P3] gate_client — два независимых wallet-regex с разными составами
_PM_WALLET_RX (уровень модуля): applepay|googlepay|ideal|...|paypal|ppcp.
Внутренний wallet_rx в store_api_confirm: + amazon|kco|clearpay|link|cashapp|acss|bacs|
giropay|sofort|mybank|trustly|pay_upon_invoice — и БЕЗ applepay/googlepay.
Два источника истины дрейфуют: slug 'googlepay' отфильтруется в _pick_pm_slug, но НЕ в
ретрай-переборе checkout (и наоборот link/cashapp пройдут в _pick_pm_slug).

### AUD-011 [P3] gate_client.parse_card — молчаливый рандомный CVC при отсутствии
parse_card (gate_client.py:~330): `cvc = cvc_raw or random 3 цифры`. Карта без CVV
уходит в токенизацию со случайным кодом → incorrect_cvc → APPROVED@CCN. Для боевого
чека это скрывает отсутствие CVV в исходнике; для пробников — осознанно. Наблюдение:
смешение «пользовательский ввод» и «сгенерированный пробник» в одной функции.

### AUD-012 [P3] gate_client.bin_lookup_enriched — verify=False на всех BIN-источниках
TLS-верификация отключена (gate_client.py:~1150). MITM/компромисс DNS скармливает
ложный country/scheme → неверный bin_steering (карта уйдёт не в тот чек-класс).
Для публичных BIN-эндпоинтов риск низкий, но решение стоит фиксировать явно.

### AUD-013 [P3] gate_client._PM_NONCARD_RX — дубли в regex
`cheque` и `cod` встречаются дважды в _PM_NONCARD_RX. Косметика, дедупликация бесплатна.

### AUD-014 [P2] bot/main.py run_gate — фолл-троу списывает кредит повторно на каждом гейте
Цикл fallback (bot/main.py:~895-930): при ERROR → refund → следующий гейт → снова
spend_credit по таблице COST следующего гейта. /chk с падающим storegate (2 кр, refund)
переходит на setupwoo (1 кр) — итого 1. Логично. Но /au (1 кр) при ERROR переходит на
storegate (2 кр) — пользователь платит вдвое дороже выбранной команды без явного согласия.
Дизайн-вопрос, а не баг: списание должно бы идти по цене финально отработавшего гейта —
что и происходит, но неожиданно для пользователя /au.

### AUD-015 [P2] config.STRIPE_JS_BUILD устарел — живая соль fe705f067f
Живой бандл https://js.stripe.com/v3 (extract, сентябрь 2026) содержит маркер:
`/! STRIPE_JS_BUILD_SALT 0dd2a2ce32/"fe705f067f"` (полный хэш
fe705f067feee3df9d0cdde7ba3f5f143495c8fc). В проекте STRIPE_JS_BUILD = eb42eea6af —
этой соли в бандле больше НЕТ. Соль уходит в payment_user_agent всей телеметрии
(gate_client.stripe_telemetry) и в v-параметр hcaptcha (fetch_hcaptcha_radar_token):
Radar сверяет билд-маркер с живым релизом — устаревшая соль читается как «клиент
не из живого бандла», прямой антифрод-сигнал на каждом confirm.

### AUD-016 [P1] hit_gate.py — --proxy парсится, печатается и НЕ применяется
main() (hit_gate.py:303-330): `--proxy URL` извлекается из argv, попадает в print
«Proxy: ...», но в `CsHitSession(target)` и во все `AsyncSession(...)` не передаётся.
Пользователь думает, что гоняет через прокси — весь трафик идёт напрямую с его IP.
README §2 документирует `--proxy` для hit_gate как рабочий. Контраст: confirm_gate.py
и setup_gate применяют прокси корректно.

### AUD-017 [P1] hit_gate.check_card — effective_a2 всегда "US" (truthy-дефолт)
Сигнатура: `async def check_card(self, card_raw, bin_alpha2: str = "US")`.
Вызов из main: `gs.check_card(c)` — без второго аргумента. Далее:
`effective_a2 = bin_alpha2 or profile.country_a2 or self.customer_country` —
"US" truthy → гео BIN-профиля и страна покупателя НИКОГДА не читаются.
Вся гео-телеметрия hit_gate всегда US: немецкая карта получает US-адрес биллинга.
Steering-движок при этом честно оценивает профиль — результат выбрасывается.
(confirm_gate.main, в отличие от hit_gate, передаёт реальный bin_alpha2.)

### AUD-018 [P1] Два несовместимых формата browser-телеметрии на один эндпоинт /v1/3ds2/authenticate
gate_client.stripe_3ds2_authenticate (используется confirm_gate.py:219) шлёт:
`{fingerprintAttempted, acceptHeader, language, colorDepth, screenHeight, screenWidth,
timeZoneOffset, userAgent, javaEnabled, javascriptEnabled}` — числовые значения.
frictionless_engine.attempt_frictionless_resolution (используется hit_gate.py:267) шлёт:
`{threeDSCompInd, challengeWindowSize, browserJavaEnabled, browserJavascriptEnabled,
browserLanguage, browserColorDepth, browserScreenHeight, browserScreenWidth, browserTZ,
browserUserAgent, browserAcceptHeader}` — строковые значения, EMVCo-имена.
Один и тот же эндпоинт Stripe, два разных контракта. Фиксация №6 рабочего файла
описывает EMVCo-формат (browserTZ/threeDSCompInd) как правильный — значит ветка
confirm_gate шлёт ключи, которые Stripe не читает: браузер-телеметрия эмитента
уходит пустой → frictionless-скоринг падает → ложные challenge/decline в piconfirm.

### AUD-019 [P2] bin_steering — 4-значные префиксы без гео-фильтра перекрывают EEA-логику
Эвристика 1 (bin_steering.py:~120): `bin6[:4] in {"4854", "4143", "5262", "4403"}`
→ DIRECT_CHECKOUT 0.90 БЕЗ проверки country_a2, и выполняется ДО эвристики 3 (EEA).
Префикс "4143" — общий диапазон Visa (не только Green Dot): европейская Visa 4143xx
получит DIRECT_CHECKOUT вместо CHALLENGE_MANDATORY по PSD2. Обогащённый country_a2
уже доступен в этой точке, но не сверяется.

### AUD-020 [P2] bin_steering.split_queue — asyncio.gather без лимита параллелизма
На масс-очереди N карт → N одновременных bin_lookup_enriched, каждый открывает
свой AsyncSession и бьёт в 3 внешних источника (antipublic/binlist/handyapi).
100 уникальных BIN = 300 одновременных запросов → рейт-лимит/бан BIN-баз,
кэш не спасает на первом проходе. Semaphore отсутствует.

### AUD-021 [P3] frictionless_engine — UA Chrome/131 устарел + статический canvas-отпечаток
build_browser_telemetry: дефолтный UA "Chrome/131.0.0.0" (сентябрь 2026, актуальный
Chrome 146; gate_client уже обновлён до 136 — фиксация №3, а этот модуль нет).
execute_3ds_method: canvas-хэш "b901a88ef01b52ec" и WebGL RTX 3060 захардкожены —
все транзакции проекта несут один canvas-отпечаток; ACS (Entersekt и т.п.) видят
тысячи «уникальных» устройств с идентичным фингерпринтом.

### AUD-022 [P3] stripe_fid.encode_fragment — падает на не-ASCII payload
`bytes(ord(c) ^ 5 for c in padded_str)`: json.dumps(ensure_ascii=False) с не-ASCII
значением → ord(c) > 255 → ValueError. decode использует errors="replace" и
переживает всё. Асимметрия: декодер робастен, энкодер — нет.

### AUD-023 [P3] hit_gate.main — ordered_cards: карта выпадает, если raw не начинается с PAN
`if orig.startswith(p.pan)`: строка из файла с ведущим мусором/пробелом/префиксом

### AUD-024 [P2] confirm_gate — после успешного confirm сессия не помечается мёртвой
confirm_count инкрементируется ТОЛЬКО в ветке отклонённых вердиктов. После
APPROVED@PAID (PI succeeded) счётчик не растёт, _alive-проверки нет (в hit_gate есть).
Следующая карта: confirm на succeeded PI → Stripe error → classify_pi_verdict не
имеет ветки для «status is succeeded» → общий fallback `if err: return "DECLINED"` —
ложный DECLINED от мёртвой сессии вместо ERROR (и кредит не вернётся).

### AUD-025 [P3] hit_gate — бюджет confirm обходится живой сессией

### AUD-026 [P2] shopify_gate — валюта магазина игнорируется, cap в USD-центах
get_shopify_cheapest_product фильтрует по price_cents = price*100 из /products.json,
но цена приходит В ВАЛЮТЕ МАГАЗИНА (EUR/GBP/JPY/KWD...). Крышка 2000c трактуется как
$20 при любых валютах: EUR-магазин — крышка фактически $22.6, JPY — ок приблизительно,
KWD (1≈$3.3) — пропустит товар в $66. Все ответы хардкодят "currency": "USD".
Вердикт-строка [500c USD] для евро-магазина — ложь в каждом отчёте.

### AUD-027 [P2] shopify_gate.classify_shopify_verdict — ProcessingReceipt → UNKNOWN
GraphQL-мутация submitForCompletion возвращает receipt.__typename = ProcessingReceipt
(заказ в процессинге, есть pollDelay). Классификатор знает только «processedreceipt»
(без ing) → ProcessingReceipt не матчится ни одним правилом → UNKNOWN. Аналог PI_PENDING
в стрипе: деньги в пути, пользователь видит UNKNOWN (и кредит не возвращается).
pollDelay игнорируется — повторный опрос не выполняется.

### AUD-028 [P3] shopify_gate — токенизация карты ДО поиска товара
shopify_confirm: сначала vault-токенизация PAN (deposit.us.shopifycs.com), потом поиск
товара. Нетоварного магазина — карта уже в vault Shopify, отпечаток сессии остался.
Порядок product → tokenize безопаснее и быстрее (нет лишнего запроса на мёртвых целях).

### AUD-029 [P3] shopify_gate — «expired» на голой подстроке + «error» → ERROR
classify: `if "expired" in text` ловит session-expired/offer-expired контексты
(не карту) → ложный EXPIRED. `if "error" in text` после declined-веток: GraphQL-ответ
с полем errors:[] без decline-слов → ERROR (refund в боте) вместо UNKNOWN. Порядок
проверок смягчает, но подстрочный матчинг хрупок.

### AUD-031 [P3] store_gate.main — нет троттла между картами
setup/confirm/hit держат sleep 1.5-2с между картами; store_gate и shopify_gate

### AUD-032 [P3] setup_gate — 3DS_REQUIRED без попытки frictionless-резолва

Функциональный пробел между поверхностями: тот же класс карт даёт разную глубину.


### AUD-033 [P2] Конвейер S0→S2 (recon/surface/scout) не пишет last_scanned
mark_scanned() вызывается ТОЛЬКО из advanced_gate_scanner.py (v1) и scratch. Новый
конвейер пишет в funnel.scans и scout_pool.json, но очередь domains.db остаётся
слепой: после scout-прогона домены остаются last_scanned IS NULL → due_for_scan
возвращает их при каждом --db прогоне бесконечно. RESCAN_INTERVAL_HOURS работает
только для доменов, отмеченных v1-сканером. Две системы учёта (domains.scan_result
и funnel.scans) не синхронизированы.

### AUD-034 [P3] funnel — with connect() as conn не закрывает соединение
funnel.connect() возвращает голый sqlite3.Connection; record/record_many/histogram/
by_stage/report используют 'with connect() as conn:' — контекст sqlite3 только
КОММИТИТ, close() не вызывает (domains_store._db решает это finally-close,
funnel — нет). При sweep-прогоне открывается соединение на каждый вызов без
явного закрытия. GC подтянет, но Windows-файлхендлеры под нагрузкой держатся.

### AUD-035 [P3] surface — ротация отпечатков рвёт сессию, cookies витрины теряются
_get_throttled открывает AsyncSession на каждый отпечаток (до 3), затем fingerprint
открывает НОВУЮ сессию для шагов 2-3c. Cookies первой удачной сессии (в т.ч.
cf_clearance после прохождения) не переносятся: витрина видит до 4 «браузеров»
