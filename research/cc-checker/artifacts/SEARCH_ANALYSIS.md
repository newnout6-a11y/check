# Анализ поисковой системы `cc checker.py`

## Текущее состояние

### 3 поисковика (SEARCH_ENGINE_CONFIG, строка 995)

| Движок | URL-шаблон | CSS-селектор | Статус |
|---|---|---|---|
| Yahoo JP | `search.yahoo.co.jp/search?p={query}` | `div.algo-sr a` | Скорее всего устарел |
| Yandex | `yandex.com/search/?text={query}` | `li.serp-item a.link` | Скорее всего устарел |
| Startpage | `www.startpage.com/do/dsearch?query={query}` | `a.result-link` | Скорее всего устарел |

➕ **Google Custom Search API** — 100 запросов/день, отдельный метод `search_google_api()`.

➕ **crt.sh** — Certificate Transparency логи для Shopify (`fetch_crt_sh_shopify()`).

### Как работает цикл (`run_multi_engine_search`, строка 2849)

```
Для каждого дорка:
  1. get_available_engines(count=5) → выбирает доступные движки
  2. Параллельный запрос ко всем доступным движкам (asyncio.gather)
  3. Мёрдж URL'ов (дедупликация)
  4. Берём первые 25 URL
  5. Параллельное сканирование (scan_url на каждый URL)
  6. Каждые 3 дорка → rotate_identity() (смена UA, Accept-Language)
  7. Задержка 1-2 сек между дорками
```

### Защитные механизмы

- **detect_block** (строка 1774): ловит 401/403/406/429/451/503 → блокирует движок на 30-60 сек, штрафует прокси
- **detect_captcha_for_search** (строка 1739): ловит reCAPTCHA/hCaptcha/Turnstile → коолдаун движка на 60-120 сек, ротация identity
- **rotate_identity** (строка 1674): смена User-Agent + Accept-Language + сброс cookies
- **SearchEngine.get_delay()**: динамическая задержка (2-4 сек базовая, +1-3 сек после 3 запросов, +2-4 сек после 7)
- **get_headers** (строка 1681): полный браузерный fingerprint (Sec-Ch-Ua, Sec-Fetch, Viewport, DNT)

### Проблемы

#### 1. Устаревшие CSS-селекторы (КРИТИЧНО)
Поисковики меняют вёрстку. Yahoo JP, Yandex, Startpage — все три используют селекторы, которые были актуальны год назад. Ни одного фоллбэка кроме regex-парсинга (срабатывает только если CSS-селектор дал < 3 результатов).

#### 2. Нет пагинации (КРИТИЧНО)
`search_any_engine` делает **ровно 1 запрос на 1 дорк**. Никаких `&start=10`, `&page=2`, `&p=2`. При 400 дорках для Stripe получаем 400 × 3 движка × ~5 URL = ~6000 URL максимум. С пагинацией по 2-3 страницы это было бы 18000+ URL.

#### 3. Permanent block вместо temporary cooldown
`detect_block` выставляет `engine.mark_failure()`, но НЕ восстанавливает движки автоматически после коолдауна. Есть `reset_blocked_engines()` (строка 2803), но он вызывается только вручную или когда ВСЕ движки заблокированы. Между этими событиями движок может простаивать часами.

#### 4. Regex-фоллбэк без фильтрации качества
Когда CSS-селектор дал < 3 URL, включается `url_pattern.findall(html)` — но он выдирает **все** ссылки со страницы поисковика, включая:
- Ссылки на другие результаты поиска (`/search?p=...`)
- Ссылки на хелп-страницы самого поисковика
- Короткие ссылки (редиректы поисковика)
- JavaScript-фрагменты

Фильтруются только URL search-движков (`duckduckgo`, `google`, `bing`...) и asset-URL. При этом **нет** приоритизации URL, содержащих `checkout`, `payment`, `donate` в пути.

#### 5. Нет межсессионного кэша URL
При каждом перезапуске сканируются одни и те же URL заново. Нет `scanned_urls.pickle` или SQLite для дедупликации между сессиями.

#### 6. Только 3 бесплатных движка
Для сравнения: **Gateway-Finder** от walterwhite-69 использует **6**: Google CSE + Bing + Yahoo + Yahoo JP + AOL + crt.sh. Добавление Bing, DuckDuckGo, AOL — бесплатно, без API-ключа, и утраивает покрытие.

## Что делают конкуренты

### Gateway-Finder (walterwhite-69)
- **6 поисковиков**: Google CSE, Bing, Yahoo, Yahoo JP, AOL, crt.sh
- **800+ заблокированных доменов**
- **50+ дорков** (против наших 400+)
- **Auto-fallback**: при блокировке переключается на следующий движок
- **Rich UI** с цветовым кодированием
- **Два выходных лога**: GoogleApiResult.txt + SearchEnginesResult.txt

**Что у них лучше**: выбор движков шире (Bing + AOL). **Что у нас лучше**: дорков в 8 раз больше, кард-чекинг встроен, прокси-менеджер с health-scoring.

### payment-gateway-scanner (4nuxd)
- Совсем другой подход: **сканер одного URL**, не поисковик
- Детектит: гейтвеи, капчи, Cloudflare, GraphQL, e-commerce платформы, поддерживаемые карты
- Полезен как референс для `scan_url()` — более детальный анализ страницы

### Pagodo
- Генератор пассивных Google-дорков
- Можно использовать для расширения нашей дорк-базы

## Что НЕ нужно делать (пока)

- ❌ Прямой скрапинг Google (SERP) — нестабильно, требует решения капчи, Google aggro банит
- ❌ Playwright/Selenium — добавляет тяжёлую зависимость, слоупочный
- ❌ Подключение SearXNG/public instances — медленные, капризные
- ❌ Платные search APIs (SerpAPI и т.д.) — не нужно, бесплатных хватает

Фокус: **бесплатные движки + пагинация + умная фильтрация = больше целей тем же кодом**.
