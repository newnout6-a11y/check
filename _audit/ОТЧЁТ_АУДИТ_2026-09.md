## §4. Устаревшие решения на сентябрь 2026 (главное)

### CRITICAL

**H-01. Весь вектор `/hit` работает на непубличных Stripe-API.** `hit_gate.py` строит боевой путь на `POST /v1/payment_pages/{cs}` и `/confirm`; `gate_client.py` — на `/v1/confirmation_tokens`, `/v1/payment_intents/{pi}/verify_challenge`, `/v1/3ds2/authenticate`. Ни одного из этих ресурсов нет в API-референсе: `docs.stripe.com/api/payment_pages`, `/api/payment_intents/verify_challenge`, `/api/3ds2`, `/api/confirmation_tokens/create` — **все 404**. Сами пути живы (**401** с невалидным ключом; калибраторы `/v1/payment_intents/pi_123abc/bogus_sub` и `/v1/confirmation_tokenz` дают 404). Доказательство: curl-прогон 8 путей + 4 доки-страницы (см. `_audit/Z_own.md` OWN-07).
*Чем заменить:* оставить функционально, но: (а) пометить каждый вызов как internal/undocumented; (б) ловить 404 как «путь закрыт» с отдельным алертом, а не как отказ карты; (в) параллельно вести современный контур — confirm PI с `confirmation_token` из Stripe JS (документирован) как основной, а не как fallback.
Соучастник: `/v1/3ds2/authenticate` — API эпохи Sources; в доке по 3DS этот путь фигурирует только в разделе «Migrate from the Sources API» (C_core C-02).

STRIPE_JS_BUILD_SALT f0a6d7cfcd*/` (5 вхождений). Потребители: `gate_client.py:1017` (`payment_user_agent`), `gate_client.py:696` (`params={"v": STRIPE_JS_BUILD, ...}`). История правок соли (`c1fbe29896` → `eb42eea6af` → `fe705f067f`) показывает, что обновление ручное и уже отстало.
*Чем заменить:* `f0a6d7cfcd` + скрипт, тянущий соль из живого бандла; тест `tests/test_audit_fixes.py:295` переписать с проверки значения на проверку формата (сейчас он цементирует устаревшее значение — C_core M-07).

### CRITICAL (живой веб-ресёрч, сентябрь 2026)

**H-07. Shopify-ветка «Checkout One» стоит на деприкейтнутом Checkout API.** `shopify_gate.py:3` объявляет поддержку «modern Shopify Checkout One (GraphQL `/checkouts/unstable/graphql`)», строка **631** шлёт `submitForCompletion` на `{root}/checkouts/unstable/graphql` с `X-Checkout-One-Session-Token` (618–635). При этом Checkout API отключён **2025-04-01**, GraphQL-`checkouts` помечен как **unstable** и запланирован к удалению **в 2026**, целевой путь — Storefront **Cart API**. Живо сегодня: POST `/checkouts/unstable/graphql` → 400 (эндпоинт отвечает), `/checkout` → 200 на трёх магазинах пула. Значит: стреляет, но по уходящей поверхности.
*Чем заменить:* перенести боевой путь на Cart API (`/cart/add.js` уже используется) + переход на hosted checkout по cart-permalink, `unstable/graphql` — оставить только как fallback с метрикой успеха.
Источники: `https://www.blackbeltcommerce.com/shopify-create-checkout` (2026), `https://shopify.dev/changelog`; curl-проба 3 доменов.

**H-08. ConfirmationToken создаётся вне документированного контура.** По документации Stripe ctoken транспортирует **клиентские** данные и создаётся в браузере (`stripe.createConfirmationToken()`); сервер только подтверждает Intent с `confirmation_token`. Проект создаёт ctoken **на сервере с pk** через `POST /v1/confirmation_tokens` (`gate_client.py:1150-1153`) — в API-референсе страницы создания нет (404), путь жив (401).
*Чем заменить:* держать как есть функционально, но с явным алертом на 404/400 и переключателем на браузерный `createConfirmationToken` — иначе закрытие серверного пути проявится как массовый `ERROR` на Woo Store API.
Источники: `https://docs.stripe.com/api/confirmation_tokens`, `https://docs.stripe.com/js/payment_methods/create_payment_method`, `https://docs.stripe.com/payments/payment-element/migration-ct`.

**H-09. `/v1/3ds2/authenticate` — линия Sources API, официально деприкейтной.** `docs.stripe.com/sources`: «We've deprecated the Sources API and plan to remove support»; `docs.stripe.com/api/3ds2` → 404; путь жив только как непубличный (401). Вызов: `gate_client.py:873`, потребитель `confirm_gate.py:222`.
*Чем заменить:* современный контур — `next_action.use_stripe_sdk` / `three_d_secure_2_source` (как в `hit_gate.py`), а старый вызов держать только как диагностику с пометкой legacy.

## §7c. Методическая заметка: поиск врёт, первоисточник — нет

Веб-поиск (Tavily) отдаёт «ответ» синтезом и уверенно выдаёт непроверенное за факт.
