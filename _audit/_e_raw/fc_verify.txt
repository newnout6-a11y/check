class="clean-btn tocCollapsibleButton_TO0P">On this page</button></div><div class="theme-doc-markdown markdown"><header><h1>Verify the response</h1></header>
<blockquote>
<p>The verification is almost the same as Google&#x27;s ReCAPTCHA, so it should be easy to switch between the two (either direction).</p>
</blockquote>
<p>In the form data sent to the server, there will be an extra text field called <code>frc-captcha-solution</code>. We will send this string to the Friendly Captcha servers to verify that the CAPTCHA was completed successfully.</p>
<h2 class="anchor anchorWithStickyNavbar_LWe7" id="creating-a-verification-request">Creating a verification request<a href="#creating-a-verification-request" class="hash-link" aria-label="Direct link to Creating a verification request" title="Direct link to Creating a verification request">​</a></h2>
<p>You will need an API key to prove it&#x27;s you, you can create one on the <a href="https://app.friendlycaptcha.eu/dashboard" target="_blank" rel="noopener noreferrer"><strong>API Keys page</strong></a> in the dashboard.</p>
<p>To verify the CAPTCHA solution, make a POST request to <code>https://api.friendlycaptcha.com/api/v1/siteverify</code> with the following parameters:</p>
<table><thead><tr><th>POST Parameter</th><th>Description</th></tr></thead><tbody><tr><td><code>solution</code></td><td>The solution value that the user submitted in the <code>frc-captcha-solution</code> field</td></tr><tr><td><code>secret</code></td><td>An API key that proves it&#x27;s you, create one on the Friendly Captcha website</td></tr><tr><td><code>sitekey</code></td><td><strong>Optional:</strong> the sitekey that you want to make sure the puzzle was generated from.</td></tr></tbody></table>
<p>You can pass these parameters in a JSON body, or as formdata.</p>
<blockquote>
<p>If your account is on the <strong>Advanced</strong> or <strong>Enterprise</strong> plan your server can also make a request <a href="/docs/v1/guides/eu-endpoint">to our EU endpoint</a>.</p>
</blockquote>
<h2 class="anchor anchorWithStickyNavbar_LWe7" id="the-verification-response">The verification response<a href="#the-verification-response" class="hash-link" aria-label="Direct link to The verification response" title="Direct link to The verification response">​</a></h2>
<p>The response will tell you whether the CAPTCHA solution is valid and hasn&#x27;t been used before. The response body is a JSON object:</p>

<p>If <code>success</code> is false, <code>errors</code> will be a list containing at least one of the following error codes below. <strong>If you are seeing status code 400 or 401 your server code is probably not configured correctly.</strong></p>
<table><thead><tr><th>Error code</th><th>Status</th><th>Description</th></tr></thead><tbody><tr><td><code>secret_missing</code></td><td>400</td><td>You forgot to add the secret (=API key) parameter.</td></tr><tr><td><code>secret_invalid</code></td><td>401</td><td>The API key you provided was invalid.</td></tr><tr><td><code>solution_missing</code></td><td>400</td><td>You forgot to add the solution parameter.</td></tr><tr><td><code>bad_request</code></td><td>400</td><td>Something else is wrong with your request, e.g. your request body is empty.</td></tr><tr><td><code>solution_invalid</code></td><td>200</td><td>The solution you provided was invalid (perhaps the user tried to tamper with the puzzle).</td></tr><tr><td><code>solution_timeout_or_duplicate</code></td><td>200</td><td>The puzzle that the solution was for has expired or has already been used.</td></tr></tbody></table>
<blockquote>
<p>⚠️ Status code 200 does not mean the solution was valid, it just means the verification was performed succesfully. Use the <code>success</code> field.</p>
</blockquote>
<p>A solution can be invalid for a number of reasons, perhaps the user submitted before the CAPTCHA was completed or they tried to change the puzzle to make it easier. The first case can be prevented by disabling the submit button until the CAPTCHA has been completed succesfully.</p>
<h2 class="anchor anchorWithStickyNavbar_LWe7" id="verification-best-practices">Verification Best practices<a href="#verification-best-practices" class="hash-link" aria-label="Direct link to Verification Best practices" title="Direct link to Verification Best practices">​</a></h2>
<p>If you receive a response code other than 200 in production, you should probably accept the user&#x27;s form despite not having been able to verify the CAPTCHA solution.</p>
<p>Maybe your server is misconfigured or the Friendly Captcha servers are down. While we try to make sure that never happens, it is a good idea to assume one day disaster will strike.</p>
<p>An example: you are using Friendly Captcha for a sign up form and you can&#x27;t verify the solution, it is better to trust the user and let them sign up anyway, because otherwise no signup will be possible at all. Do send an alert to yourself!</p>
