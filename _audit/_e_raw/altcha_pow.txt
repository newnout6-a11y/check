id="proof-of-work-pow">Proof of Work (PoW)</h1> <p>ALTCHA Proof-of-Work (PoW) v2 is a sophisticated, client-side computational puzzle designed to protect web applications from automated abuse. Unlike traditional PoW systems that rely on simple hashing, ALTCHA PoW v2 utilizes <strong>Key Derivation Functions (KDFs)</strong> to create an asymmetric challenge: expensive for the client to solve, but cheap for the server to verify.</p> <p>For more technical details about the PoW, visit the <a href="https://playground.altcha.org/#/about" rel="nofollow">Playground</a>.</p> <h2 id="core-algorithms">Core Algorithms</h2> <p>ALTCHA supports multiple cryptographic primitives to balance device compatibility with hardware resistance.</p> <div class="table-scroll"><table><thead><tr><th align="left">Algorithm</th><th align="left">GPU/ASIC Resistance</th><th align="left">Browser Implementation</th><th align="left">Server Verification</th></tr></thead><tbody><tr><td align="left"><strong>PBKDF2</strong></td><td align="left">Low</td><td align="left">Native (<code>SubtleCrypto</code>)</td><td align="left">Very Fast</td></tr><tr><td align="left"><strong>Argon2id</strong></td><td align="left">Maximum</td><td align="left">WASM</td><td align="left">Moderate</td></tr><tr><td align="left"><strong>Scrypt</strong></td><td align="left">Moderate</td><td align="left">WASM</td><td align="left">Moderate</td></tr><tr><td align="left"><strong>SHA</strong></td><td align="left">Very Low</td><td align="left">Native (<code>SubtleCrypto</code>)</td><td align="left">Very Fast</td></tr></tbody></table></div> <h3 id="memory-hard-protection">Memory-Hard Protection</h3> <p>To counter attackers using specialized hardware (GPUs/ASICs), ALTCHA leverages <strong>Argon2id</strong> and <strong>Scrypt</strong>. These algorithms require significant RAM to compute, narrowing the performance gap between a standard smartphone and a specialized bot farm.</p> <h2 id="effort-modes">Effort Modes</h2> <p>The mechanism operates in two distinct modes, allowing developers to prioritize either user experience consistency or server scalability.</p> <h3 id="1-deterministic-effort-mode-recommended">1. Deterministic Effort Mode (Recommended)</h3> <p>The server defines the exact amount of work required. By pre-calculating a target and providing a <code>keySignature</code>, the server ensures the user spends a predictable amount of time solving the challenge.</p> <ul><li><strong>User Experience:</strong> Highly consistent and predictable.</li> <li><strong>Verification:</strong> Extremely fast (uses HMAC validation).</li> <li><strong>Best For:</strong> Standard web forms, login protection, and security-sensitive APIs.</li></ul> <h3 id="2-probabilistic-effort-mode">2. Probabilistic Effort Mode</h3> <p>The server sets a statistical difficulty (e.g., "find a result starting with <code>00</code>"). The client solves challenges based on "luck," meaning some challenges are solved instantly while others take longer.</p> <ul><li><strong>User Experience:</strong> Variable; solving time fluctuates.</li> <li><strong>Server Cost:</strong> Near-zero overhead for challenge generation.</li> <li><strong>Best For:</strong> High-throughput endpoints, IoT, or edge computing.</li></ul> <h2 id="technical-workflow">Technical Workflow</h2> <p>The PoW process follows a three-step lifecycle:</p> <h3 id="1-challenge-generation">1. Challenge Generation</h3> <p>The server creates a JSON payload containing the <code>algorithm</code>, <code>salt</code>, <code>nonce</code>, and difficulty parameters (<code>cost</code>, <code>keyPrefix</code>). In <strong>Deterministic Mode</strong>, a <code>keySignature</code> is included.</p> <h3 id="2-client-solving">2. Client Solving</h3> <p>The client executes a loop, incrementing a <code>counter</code> and deriving a key until the output matches the server's requirements:</p> <p><code>DerivedKey=KDF(Algorithm, Salt, Cost, Password)</code></p> <p>Where <code>Password</code> is the <code>nonce</code> appended with the <code>counter</code>.</p> <h3 id="3-server-verification">3. Server Verification</h3> <p>The server validates the solution by checking the HMAC signature of the parameters and performing a single KDF execution to ensure the submitted <code>counter</code> produces the claimed <code>derivedKey</code>.</p> <h2 id="configuration--best-practices">Configuration &amp; Best Practices</h2> <p>To ensure a smooth experience for legitimate users while deterring bots, use these recommended settings:</p> <h3 id="for-wide-compatibility-pbkdf2">For Wide Compatibility (PBKDF2)</h3> <p>PBKDF2 is the best default for most applications as it runs natively in the browser without extra binaries.</p> <ul><li><strong>Algorithm:</strong> <code>PBKDF2</code> (SHA-256)</li> <li><strong>Cost:</strong> <code>5000</code></li> <li><strong>Counter (Deterministic):</strong> <code>5000</code> to <code>10000</code></li></ul> <h3 id="for-maximum-security-argon2id">For Maximum Security (Argon2id)</h3> <p>Use Argon2id to force attackers to exhaust physical RAM, making large-scale flood attacks expensive.</p> <ul><li><strong>MemoryCost:</strong> <code>65536</code> to <code>131072</code> (64MB to 128MB)</li> <li><strong>Parallelism:</strong> <code>1</code></li> <li><strong>Counter (Deterministic):</strong> <code>100</code> to <code>200</code></li></ul><!----></div><!--]--> <!--[0--><nav class="mt-12 flex items-stretch gap-4 border-t
