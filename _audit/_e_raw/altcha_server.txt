13v6a2 2 0 0 1-2 2H5a2 2 0 0 1-2-2V8a2 2 0 0 1 2-2h6"><!----></path><!----><!--]--><!----></svg><!----></a><!--]--></div><!----> <h2 id="challenge-generation">Challenge Generation</h2> <p>Your server must generate a fresh, single-use challenge for each user interaction. The widget requests a new challenge from the configured URL when the user begins verification.</p> <p><a href="/docs/sentinel/">ALTCHA Sentinel</a> provides a built-in API endpoint, <a href="/sentinel-api-docs-v1.html#tag/challenge/get/v1/challenge"><code>GET /v1/challenge</code></a>. Custom server integrations should expose a comparable endpoint that returns a newly generated challenge on every request.</p> <p>For an overview of the complete workflow, see the <a href="/docs/integration/diagrams/">verification diagram</a>.</p> <h2 id="server-verification">Server Verification</h2> <p>After the widget verifies the user, you must cryptographically <strong>verify the ALTCHA payload submitted by the widget on your server</strong>. The payload is a Base64-encoded JSON string, typically submitted as a form field named <code>altcha</code> (this can be customized using the <code>name</code> attribute in the widget).</p> <p>This verification usually occurs in your form submission handler (e.g., a <code>POST /submit</code> endpoint) where the form data is processed.</p> <p>When using the library, verification is entirely cryptographic and requires no API calls, making it efficient and fast.</p> <h3 id="verifying-with-altcha-sentinel">Verifying <ins>with ALTCHA Sentinel</ins></h3> <h4 id="a-using-the-library">a) Using the Library</h4> <p>When using the <a href="/docs/sentinel/">ALTCHA Sentinel</a> server, verify the payload with the <strong><code>verifyServerSignature</code></strong> function from the ALTCHA library.
Use the <strong>API key secret</strong> generated by ALTCHA Sentinel as the HMAC key.</p> <p>For supported environments, see <a href="/docs/integration/server/#libraries">Libraries and Plugins</a>. Currently supported environments include <strong>TypeScript, Dart, Go, Python, Java, Elixir, PHP, Ruby, Rust, and C++</strong>.</p> <p>For an overview of the verification flow, refer to the <a href="/docs/integration/diagrams/#1-sentinel-verification">verification diagram</a>.</p> <h4 id="b-using-the-http-api">b) Using the HTTP API</h4> <p>For enhanced protection against <a href="/docs/integration/security-recommendations/#replay-attacks-with-server-signatures">replay attacks</a>, or if a library is not available in your environment, you can use the <a href="/sentinel-api-docs-v1.html#tag/verify/post/v1/verify/signature"><code>POST /v1/verify/signature</code></a> endpoint to verify the payload.</p> <p>The API endpoint is public and does not require authentication.
In addition to the <code>verified</code> boolean, the response includes <code>apiKey</code> and parsed <code>verificationData</code>. See the <a href="/sentinel-api-docs-v1.html#tag/verify/post/v1/verify/signature">API documentation</a> for more details.</p> <p>The endpoint includes built-in protection against replay attacks: it will return <code>verified: true</code> only once, on the first valid request.</p> <h3 id="verifying-without-altcha-sentinel">Verifying <ins>without</ins> ALTCHA Sentinel</h3> <p>For solutions <strong>not using ALTCHA Sentinel</strong>, use the verification functions provided by the <a href="/docs/integration/server/#libraries">libraries</a>. Each library’s documentation contains specific implementation details.</p> <p>A custom server integration requires implementing an HTTP endpoint to generate new challenges. Configure this endpoint as the <code>challenge</code> URL in the widget.</p> <h2 id="related-documentation">Related Documentation</h2> <ul><li><a href="/docs/integration/diagrams/">Server Verification
