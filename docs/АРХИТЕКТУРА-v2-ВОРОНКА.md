## 0. Отправная точка: почему 0 из 933

Живое состояние на входе в раунд (`scratch/_doc_audit.py`):

```
domains.db: total=992  scanned=933  pending=59
by_result : NO_REG=926  CAPTCHA_ADDCARD=7  READY=0
ready_gates.json: 1 запись (наследие прошлых раундов, не из этого скана)
```

Воронка отдаёт **ноль**. Но `NO_REG` — это не diagnosis, это мусорная корзина: туда
попадает и «домена нет», и «сайт жив, это Shopify, просто не Woo», и «регистрация
закрыта», и «test-mode Stripe», и «таймаут». **926 записей без причины = 0 бит
информации.** Нельзя улучшить то, что не измеряется.

Это корневой дефект архитектуры, а не настройка. Всё ниже — его разворот.

## 1. Пять слоёв

```
S0  SOURCES      полосы добычи → (domain, source, evidence, trust)
      ↓
S1  IDENTITY     отпечаток: платформа · платёжный стек · гео · цена · живость
      ↓              ~3 дешёвых запроса, причина отказа из закрытого enum
S2  ROUTING      отпечаток → множество ВОЗМОЖНЫХ векторов (отсечь невозможное дёшево)
      ↓
S3  CAPABILITY   проба каждого вектора: дешёвая → дорогая, своя причина на каждый шаг
      ↓
S4  LIVE         боевой чек probe-картой ($0-auth или минимальная авторизация)
      ↓
S5  POOL         SR · EMA-латентность · fail_count · TTL · prune · phantom-контроль
      ↑______________________________ телеметрия вердиктов замыкает петлю ______|
```

Ключевое отличие от v1: **каждый слой пишет причину, а не только результат.** S1 и S3
не «проваливают» кандидата — они **классифицируют провал**. Из 926 `NO_REG` должна
получиться гистограмма, по которой видно, что чинить в первую очередь.

### 1.1 Принцип дешёвого отсечения

Стоимость кандидата растёт на порядок на каждом слое. Отсекать надо максимально рано:

| Слой | Цена на домен | Что отсекает |
|---|---:|---|
| S0 | ~0.01 запроса (поисковик/индекс) | нерелевантные темы, мусорные TLD |
| S1 | 1–3 запроса, только GET | не-Woo и не-Shopify, test-mode, Cloudflare, мёртвый DNS |
| S2 | 0 запросов (чистая логика) | векторы, невозможные для данной платформы |
| S3 | 5–15 запросов, есть POST | закрытая регистрация, нет pk, нет nonse |
| S4 | 15–40 запросов, **токенизация карты** | неживой гейт, фантомы, капча |
| S5 | 0 | протухшие, за_rate-limited, фантомные |

v1 тратила S3–S4 на всё подряд. Отсюда и 933 просканированных при нуле на выходе,
и домашний IP в банах.

## 3. S1 — отпечаток поверхности

Один дешёвый проход, три GET, никаких POST, никаких мутаций:

```
GET /                          → платформа, pk_live, валюта, lang, цена
GET /wp-json/wc/store/v1/cart  → Woo Blocks? nonce, payment_methods (слаги!)
GET /products.json             → Shopify? catalog + цены
```

Отпечаток:

```python
{
  "domain": ..., "canonical_host": ...,   # редирект 301/302 разрешён ОДИН раз
  "platform": "woo_blocks"|"woo_legacy"|"shopify"|"other",
  "payments": {"stripe_pk": "pk_live_...", "methods": ["stripe_cc","ppcp"],
               "braintree": false, "secret_exposed": false},
  "geo": {"tld": "au", "currency": "AUD"},
  "cheapest_cents": 170,
  "alive": true, "cf": false, "captcha": false,
  "reason": null | "<FAIL_REASON>"
}
```

### 3.1 Закрытый enum причин

Это ядро раунда. `NO_REG` разделяется на:

```
DNS_FAIL · TLS_FAIL · TIMEOUT · HTTP_4XX · HTTP_5XX
CF_CHALLENGE · CAPTCHA · NOT_WORDPRESS · NOT_WOO
NO_STORE_API · NO_STRIPE_PK · TEST_MODE_PK · NO_PRODUCTS
NO_PRODUCT_UNDER_CAP · GUEST_CHECKOUT_DISABLED
REG_CLOSED · ADD_ITEM_NO_JSON · ADD_ITEM_REJECTED · PM_SLUG_MISSING
```

Каждая причина — **действие**, а не наблюдение:

| Причина | Что делать |
|---|---|
| `CF_CHALLENGE` | нужен прокси; домен не отбрасывать, заморозить |
| `NO_PRODUCT_UNDER_CAP` | домен годен, поднять крышку или ждать распродажи |
| `PM_SLUG_MISSING` | баг нашего пикера — чинить код, не домен |
| `NOT_WOO` | проверить Shopify-ветку, потом выбросить |

## 4. S2 — роутинг векторов

Отпечаток → множество возможных векторов. **v1 был прибит к одному** (`setupwoo`):
сайт без открытой регистрации выбрасывался, даже если его Store API работает.

| Вектор | Требования по отпечатку |
|---|---|
| `setupwoo` | woo + `reg_nonce` + `pk_live` + add-payment-method |
| `storegate` | woo_blocks (`/cart` отдаёт nonce) + товар под крышкой |
| `shopify` | `products.json` 200 + JSON |
| `piconfirm` | `secret_exposed` (торчащий `pi_.._secret_..`) |
| `braintreenvbv` | `braintree` маркер с валидным `authorizationFingerprint` |
| `hit` | готовый `cs_live`-линк |

Один домен может дать **несколько** векторов. Пул растёт не числом сайтов, а числом
рабочих маршрутов на сайте.

## 5. S3 — capability-пробы и инвариант мутаций

**Главный инвариант раунда (D-22):**

> Любой запрос, который что-то меняет (`add-item`, `update-customer`, `checkout`),
> считается успешным **только если ответ — JSON ожидаемой формы**.
> Код ответа `200` **не является** доказательством успеха.

Подтверждено боем (см. §7): `POST /cart/add-item` отдал `302 → /product/...`,
curl_cffi дошёл по редиректу, получил `200 text/html`, и v1 принял это за
«товар добавлен». Корзина осталась пустой, checkout ответил
`409 woocommerce_rest_cart_empty`. **Тихий фантом.**

Проверка-заглушка на все мутации:

```python
def mutation_ok(resp, expect_key=None) -> tuple[bool, str]:
    ct = (resp.headers.get("content-type") or "").lower()
    if "json" not in ct:
        return False, "NON_JSON_RESPONSE"
    try:
        j = resp.json()
    except Exception:
        return False, "UNPARSEABLE_JSON"
    if expect_key and not j.get(expect_key):
        return False, f"MISSING_{expect_key.upper()}"
    return True, ""
```

## 6. S4/S5 — бой и петля обратной связи

Петля уже есть (`fail_count`, EMA-латентность, TTL, phantom-контроль). Что ломает её:

**D-26 — `DECLINED` считается «не верифицирован».** Отказ банка — это доказательство,
что поверхность жива и доводит карту до эмитента. В `store_gates.json`
девять записей с `verify_status=DECLINED` помечены `verified=false` и **выключены из
ротации**, хотя это шесть живых поверхностей. Пул душит собственная таксономия.

Правило: **верифицировано = запрос дошёл до банка.** `DECLINED`, `WRONG_CVC`,
`3DS_*` — это `verified=true`. Не верифицировано только `ERROR`.

### 7.2 Живые замеры

**wisdomofplanets.com** — канонический хост `www.`, `301` с голого домена:

```
GET  /wp-json/wc/store/v1/cart          200  nonce=ee1b28e21a  cart-token=eyJhbGciOiJIUz…
     payment_methods = ['stripe_cc', 'stripe_applepay', 'ppcp']
POST /cart/add-item  params  → 302  Location: /product/gemstone-recommendation/
POST /cart/add-item  json    → 302  (то же)
POST /cart/add-item  +Cart-Token → 302 (то же)   ← Cart-Token НЕ спасает
GET  /cart после этого       → items=0
```

Вывод: Store API на этом сайте перехвачен классическим `add-to-cart`-обработчиком.
`Cart-Token` ситуацию не меняет. **Лечится не обходом, а честным отказом** — мутация
без JSON-ответа это провал, и домен получает `ADD_ITEM_NO_JSON`, а не тихий успех.

**atriumcoffeeroasters.com** — работает:

```
POST /cart/add-item id=7808 → 201  items=1  total=600
POST /cart/add-item id=369 (variable) → 400
      woocommerce_rest_missing_attributes: Missing attributes for variable product
```

Variable-товары требуют вариацию — отдельная причина, отдельная обработка (D-24).
Этот же сайт падал на `payment_method_disabled: Apple Pay`, потому что
`_pick_pm_slug` не знает про `woocommerce_payments` (D-25).

**conferenziaworld.com / expattaxonline.com** — `under-cap = 0`: товаров дешевле $20
нет в принципе (1499.00 и 797.00). Это **не сбой**, это честное несовпадение с крышкой.
Текущее сообщение «out of stock?» лжёт.

### 7.3 Ложные следы (не преследовать)

- **[ложный след] «`purchasable` и `stock_status` приходят `null`, поэтому фильтр
  отсекает всё».** Проверено: `store_api_confirm` фильтрует по `prices.price`, эти поля
  не использует. Реальные поля схемы — **`is_purchasable` / `is_in_stock`** (и они
  `True`). Гипотеза не подтвердилась.
- **[ложный след] «POST деградирует в GET на редиректе non-www → www».** Проверено:
  на каноническом `www.` хосте `add-item` отдаёт тот же `302`. Дело не в редиректе.

## 8. Реестр дефектов раунда 10

| ID | P | Что | Статус |
|---|---|---|---|
| **D-22** | P0 | Мутация считается успешной по HTTP-коду: `add-item` отдал 302→HTML 200, корзина пуста, checkout 409. Тихий фантом. | **подтверждено боем** |

| **D-25** | P1 | `_pick_pm_slug` не знает `woocommerce_payments`, падает в дефолт `stripe`, которого на сайте нет → `payment_method_disabled`. Итоговый сланг не сверяется с реальным списком. | **подтверждено боем** |
| **D-26** | P1 | `DECLINED` = «не верифицирован». Живые поверхности исключены из ротации. | **подтверждено кодом** |
| **D-27** | P1 | `scan_result='NO_REG'` — мусорная корзина на 926 записей. Нет учёта потерь. | **архитектурный** |
| **D-28** | P2 | пул `payment_methods` из `/cart` — список **строк**, а не объектов. Любой `m.get("id")` падает. | **подтверждено боем** |
| **D-29** | P0 | Фантом-контроль отказоустойчив **не в ту сторону**: `phantom = st in PHANTOM_STATUSES` превращает зонд, упавший с ошибкой, в `phantom=False`, то есть в «доказано чист». `wellyou.lt` записан `APPROVED@PAID` при `probe = "pk_live not found on storefront"`. | **исправлено** (трёхзначный вердикт) |

### 9.2.1 A/B на свежих кандидатах (45 доменов, чередование, 360 запросов)

Два прогона подряд **мерять нельзя**: второй наследует рейт-лимит первого.
Первая попытка дала `Δ = −8` в пользу старого отпечатка — чистый артефакт
порядка. Правильный замер — перемешать режимы внутри прохода и повторить:

```
                  200 OK   429   403   всего   доля 200
chrome131            44    124    12     180      24.4 %
ротация пула        171      0     9     180      95.0 %
                                          Δ = +70.6 п.п.
```

Ротация не получает **ни одного 429** — вообще. `chrome131` ловит его на 69 %
запросов.

**Отдельно: пул `store_gates.json` дал `Δ = 0`.** Это не «правка не работает»,
а ошибка выжившего: эти 50 доменов *уже* прошли проверку под `chrome131`, то
есть по построению относятся к тем, кого он не режет. Замерять D-30 нужно на
свежих кандидатах, иначе прибор показывает ноль на работающей правке.

| Полоса | Выход | Вердикт |

DDG режет частые запросы: 3–4 подряд — пустая выдача. Пауза от 4 с с джиттером
и отступление при серии пустых.
