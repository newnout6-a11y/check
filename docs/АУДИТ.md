## 8. РАУНД 4 — ВНЕДРЕНИЕ НОВЫХ ПОВЕРХНОСТЕЙ (2026-08-28)

### В1. Stripe Checkout /hit — ВНЕДРЁН и доказан боем

Механика (восстановлена реверсом checkout-app бандла + live-пробами):

    cs_live-URL -> fid-фрагмент -> stripe_fid.decode_fragment (XOR-5+base64+JSON, агент) -> pk_live + cs_id
    -> GET api.stripe.com/v1/payment_pages/{cs}?key=pk  -> payment_intent (client_secret, amount, init_checksum)
    -> POST /v1/payment_methods (токенизация, наш движок)
    -> POST /v1/payment_pages/{cs}/confirm {key, eid, payment_method, expected_amount, init_checksum,
       expected_payment_method_type}  -> вердикт эмитента (402 card_declined/generic_decline на тест-линке)

- **hit_gate.py** — CLI-модуль (CsHitSession: open/check_card/close, живость PI, CHARGE_RISK-кап)
- **/hit url cc** — команда бота (кредиты 2/чек, вывод как у остальных гейтов)
- подтверждено живьём: pay.opus.pro-линк — полный цикл до эмитента
- ограничения: линки — расходник (1vpn/wispr из чатов протухли «no longer active»); после серии declined Stripe прячет PI сессии (антибрутфорс); прямые PI-confirm запрещены («cannot perform on PI created by Checkout») — только их контур

### В5. Braintree — витринный скан дал 0

- быстрый скан 572 due-доменов нашёл 13 «целей», но все — ЛОЖНЫЕ: regex ловил Google/Facebook-аналитику в base64 (eyJ...) вместо Braintree client_token
- фикс: extract_braintree_keys теперь валидирует eyJ-блоб через authorizationFingerprint
- вывод: настоящий Braintree-контент за чекаутом/логином (как в research: «braintree hard») — нужен глубокий скан Stage 3, отдельный заход

- тест доступности гейтов актуализирован: braintreenvbv следует файлу целей (сейчас пуст)

### Раунд 5 (2026-08-28, вечер): /hit — полный боевой контур

- **пул линков**: парсер chati/ -> 130 cs_live-URL (11 доменов, вкл. character.ai, scispace, ryzehosting, buy.stripe.com); валидация живости -> **14 живых** -> data/hit_targets.txt
- **классификатор confirm дописан**: 200-ответ несёт payment_intent в теле -> 3DS_REQUIRED (buy.stripe $1: карта жива, enrolled), succeeded -> APPROVED@PAID, processing -> PI_PENDING, last_payment_error -> таксономия
- **amount_mismatch-ретрай**: подписочные сессии (character.ai/opus) пересчитывают инвойс — перечитываем amount и повторяем один раз; упорный mismatch = плавающая подписка, отбой
- ограничения по факту: сессия в requires_action не переиспользуется (незавершённый 3DS); после наших confirm'ов Stripe может скрыть PI (антибрутфорс); живость линка — часы/дни
- **боевые прогоны**: buy.stripe $1 -> 3DS_REQUIRED (1.4с, полный цикл); checkout.stripe $1.96 -> requires_action; character.ai/opus -> amount_mismatch (подписки)
