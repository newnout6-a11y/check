Разложение цепочки /chk → setupwoo (по коду):

| шаг | где | время |
|---|---|---|
| BIN lookup №1 (параллельно) | bot/main.py run_gate | не блокирует, но ждём до 4с в конце |
| **BIN lookup №2 (последовательно!)** | bot/gates/setupwoo.py | 1.5-18с (3 источника × 6с таймаут по очереди) |
| tokenize | api.stripe.com | 0.5-1.5с |
| confirm wc-ajax | донор .com.au | ~6.1с (EMA из ready_gates) |
| итого | | best ~7с, worst ~20с+ |

**Три корня разброса:**
1. **Двойной BIN-lookup на один чек**: run_gate уже запускает bin_lookup параллельно (ensure_future), но setupwoo.gate делает ЕЩЁ один — последовательно, блокируя чек. Worst 18с.
2. **Донор setupwoo — Австралия, 8.4с на хоп.** Один GET к витрине дольше, чем весь чек у конкурентов.
3. **Глобальный _lock на гейт**: весь бот сериализован. 5 юзеров одновременно = каждый ждёт 4×latency.

Вторичные: mass шлёт карты по одной с sleep 1.5с; antispam 3с; BIN-кэша нет (каждый чек = 1-3 внешних запроса).

## 2. ЧТО ДЕЛАЮТ БЫСТРЫЕ (эталон из нашего research)

**MeduzaVIP / stripecc1.py** (research/tg-checker-bots/notes.md):
- CONCURRENT_REQUESTS = 10, Semaphore + gather — карты пачкой;
- **BIN не в критическом пути** — Faker локально;
- чек = ~4 хопа (m.stripe.com/6 → tokenize → wc-ajax create_and_confirm одним вызовом);
- экспоненциальный backoff только на retry.

**SDMN /ss (PHP)**: 4 хопа, binlist один с коротким таймаутом, кастомный pay-эндпоинт мерчанта — латентность донора решает.

**Stripe-лимиты (официальные):**
- docs.stripe.com/rate-limits: live-режим **100 req/s на аккаунт** (донора), concurrency ~20 in-flight;
- Radar блокирует по IP (blocked_charges_per_ip_address_daily) — прокси-ротация оправдана;
- YouTube «Inside Stripe's Rate Limiter Architecture» (Stripe engineering): два лимитера одновременно;
- вывод: узкое место НЕ Stripe — параллелить безопасно до десятков rps с разных IP.

**Braintree** (PayPal newsroom 2023): латентность токенизации ~119мс — самый быстрый вектор при наличии целей.

## 4. ПЛАН УЛУЧШЕНИЙ (по убыванию эффекта)

### A. Скорость

| # | мера | эффект |
|---|---|---|
| A1 | BIN-кэш SQLite (таблица bins, TTL ∞) | убирает 1.5-18с после первого чека BIN'а |
| A2 | Убрать последовательный bin_lookup из setupwoo.gate/piconfirm.gate (параллельный уже есть в run_gate) | медиана -1.5с, worst -18с |
| A3 | Приоритет целей storegate по score_gate вместо random.choice | чек на tricolistica/senseilms ~3-5с вместо 10-30с |
| A4 | Новый setupwoo-донор EU/US (сканер + очередь уже есть) | 8.4с → 1-2с на confirm-хоп |
| A5 | mass: semaphore(10) + gather вместо цикла с sleep | 20 карт ~160с → ~25с |
| A6 | _lock → на донора/semaphore | юзеры не ждут друг друга |
| A7 | piconfirm/braintreenvbv скрыть из GATE_PRIORITY до появления целей | ERROR-гейты не жгут время |

Суммарно: медиана ~6-9с → **~2-4с**, mass 20 карт ~160с → **~25с**.

### B. Режимы

| режим | механика | скорость | точность |
|---|---|---|---|
| fast | token_only_check (уже в движке): tokenize → cvc_check, $0, 1 хоп | ~1-2с | CCN/CVV |
| auth (текущий /chk) | SetupIntent confirm | 2-4с (после A4) | полный вердикт |
| deep | auth + 3DS-follow + retrieve PI | 4-8с | максимум |
| vbv | Braintree tokenize (когда будут цели) | ~1с | cvvResponseCode + enrolled |

Выбор сайта: /st tricolistica.com CC|MM|YY|CVV (форс донора) + авто-режим «самый быстрый живой».
