# АРХИТЕКТУРА PUSTO — полный разбор кода

> Состояние на **2026-08-30**, головной коммит `e895b59`. Прочитано: 16 корневых модулей,
> `bot/` целиком, `gate_client.py` (1 609 строк), `scratch/`, `tests/`, `data/`, `docs/`.
> Все цифры пулов сняты скриптом `scratch/_doc_audit.py` (запросы к SQLite/JSON и вызовы
> функций ротации бота), а не перенесены из прошлых версий этого документа.

---

## 1. Короткий вердикт

Это фабрика, а не набор скриптов: добыча доноров → квалификация поверхности → боевой чек →
вердикт, с телеграм-ботом как фронтендом и кредитной экономикой. Архитектурно проект крепче,
чем выглядит: единый движок вместо копипасты, плагинный реестр гейтов, SQLite-очередь вместо
txt-файлов, централизованный `config.py`, 91 тест, честная таксономия вердиктов.

Боеспособность упирается не в код, а в носители. Код готов на шести поверхностях, реально
живы **три** — `setupwoo`, `storegate`, `shopify`. Ещё одна (`hit`) технически рабочая, но
держится на расходном материале — живых `cs_live`-линках. Две (`piconfirm`, `braintreenvbv`)
без целей и возвращают `ERROR` по конструкции, а не по поломке.

до сих пор собран.

## 6. Таксономия вердиктов (`config.py`)

**24 класса** (в коде — `len(config.VERDICTS)`; README и АУДИТ раньше писали 17 и 21, оба неверны):

```
APPROVED, APPROVED@HOLD, APPROVED@PAID, APPROVED@CVV, APPROVED@CCN
DECLINED, DECLINED@DO_NOT_HONOR, DECLINED@FRAUD, DECLINED@STOLEN
INVALID, EXPIRED, WRONG_CVC, RESTRICTED
TEST_MODE, RATE_LIMITED, RETRY, PI_MINTED, PI_PENDING
3DS_REQUIRED, 3DS_FRICTIONLESS, 3DS_CHALLENGE, 3DS_REDIRECT
UNKNOWN, ERROR
```

Семантика:

```
incorrect_cvc        → APPROVED@CCN   (карта жива, PAN/exp валидны)
insufficient_funds   → APPROVED@CVV   (карта жива, CVV валиден)
stolen_card/lost     → DECLINED@STOLEN
do_not_honor/generic → DECLINED@DO_NOT_HONOR
transStatus Y        → 3DS_FRICTIONLESS → (poll) APPROVED@PAID
transStatus C        → 3DS_CHALLENGE   ← вердикт «жива и enrolled», не провал
transStatus N/R      → DECLINED
PI succeeded         → APPROVED@PAID
PI processing        → PI_PENDING      ← честное «не знаем»
Woo success без succeeded в PI → PI_PENDING
```

`HIT_VERDICTS` в корневом `config.py` — 4 класса (`APPROVED`, `APPROVED@HOLD`,
`APPROVED@CVV`, `APPROVED@CCN`); бот расширяет их `APPROVED@PAID`, `3DS_FRICTIONLESS`,
`3DS_CHALLENGE` (`bot/main.py:38`).

Различение `APPROVED@CVV` / `APPROVED@CCN` — то, что отличает чекер от бинарного валидатора:
оно говорит, *какая часть* карты верна.

## 7. Бот (`bot/`)

### 7.1 Устройство

- **Pyrogram**, polling, `Client("pusto_bot", workdir=bot/)`, `app.run()`.
- **Реестр гейтов** (`bot/gates/__init__.py:12`): автодискавери по пакету, контракт
  `async gate(cc, mm, yy, cvv, tier=None) -> (verdict, detail[, extra])`. Модуль с ошибкой
  импорта выпадает из реестра с логом, но не валит бота.
- **Экономика**: `START_CREDITS = 5`, списание атомарное (`UPDATE ... WHERE credits >= ?`
  + rowcount — lost-update фикс G-2), `refund_credit` при `verdict == ERROR`, ключи
  `/genkey` → `/redeem` (начисляют и дни, и кредиты), премиум по дням, админы бесплатно.
- **Антиспам**: 3 с на пользователя, на всех платных точках входа.
- **Гарды**: `user_only` (`from_user is None` в каналах), `admin_only`, `html.escape` в выводе.
- **`/mass`**: `Semaphore(5) + gather + stop_evt`, до 20 карт, разбиение вывода по 3 900 символов.
- **`/hit`**: до 10 карт, свежая HTTP-сессия на каждую (разные TLS/куки), авто-детект смерти линка.
- **Взвешенная ротация**: `_pick_target` по измеренной латентности (1/lat), неизвестные цели
  получают медианный вес — новые цели тоже исследуются.
- **Авто-выбор `/chk`**: `GATE_PRIORITY = [setupwoo, storegate, shopify, piconfirm,
  braintreenvbv]`, `_available_gates()` оставляет только гейты с целями. Сейчас
  `['setupwoo', 'storegate', 'shopify']`.

### 7.2 Команды

Пользовательские:
`/start` `/cmds` `/help` `/me` `/key|/redeem` `/chk` `/au` `/st [1|5|20]` `/sp [1|5|20]`
`/pi` `/vbv` `/b3` `/hit` `/mass [гейт]` `/bin` `/gates` `/stats` `/proxy`

Алиасы гейтов (`bot/main.py:68`): `au`→setupwoo, `st`→storegate, `sh`→storegate,
`sp`→shopify, `pi`→piconfirm, `vbv`→/`b3`→braintreenvbv.

Переменные окружения: `PUSTO_BOT_TOKEN`, `PUSTO_TG_API_ID`, `PUSTO_TG_API_HASH`,
`PUSTO_ADMINS`, `PUSTO_START_CREDITS`, `PUSTO_CREATOR_NICK`, и цели гейтов —

### D-11 · P2 · `confirm_gate.py:158` возвращает вердикт вне таксономии — **ИСПРАВЛЕНО (раунд 9)**

```python
return {"card": card_raw, "status": f"DECLINED@{code.upper()}", ...}
```

Классы вида `DECLINED@INCORRECT_CVC` отсутствуют в `config.VERDICTS`: иконка `·`,
статистика хитов не считает такие исходы, и — чего этот дефект не называл — вердикт
не равен `"ERROR"`, поэтому `bot/main.py:413` **не возвращал кредит**. Пользователь
платил за исход, который движок даже не начал.
Фикс: `gc.classify_verdict(f"{msg} {code}")`, как в `setup_gate.py:378`.

**Уточнение:** точка была не одна. `setup_gate.py:412` отдавал сырой `str(st).upper()`
— `CANCELED`, `PROCESSING`, `REQUIRES_PAYMENT_METHOD` — с тем же эффектом. Документ
знал только про `confirm_gate.py:158`. См. D-14.

### D-12 · P2 · Подписи тиров в меню врут для Shopify — **ИСПРАВЛЕНО (раунд 9)**

`TIER_LABELS` (`bot/main.py:99`; в документе значилось `:88` — устарело): `low` — `<$1`,
`mid` — `$1–5`, `high` — `$5–20`. Для `storegate` верно (`low = (0,100)`), для `shopify` —
нет: `low = (0,200)`, `mid = (201,600)`, `high = (601,2000)`.

**Уточнение:** врали **все три** подписи, а не только `low`: `mid` у Shopify — это
`$2.01–6`, `high` — `$6.01–20`. Фикс: `tier_label()` считает подпись из `PRICE_TIERS`
целевого гейта, а не из общей строки. Расхождение границ между гейтами осознанное,
поэтому источник истины должен быть один — таблица самого гейта.

### D-13 · P2 · `requirements.txt` и импорт бота расходятся — **СНЯТ: дефекта нет**

Проверено 2026-08-31: **kurigram — это форк pyrogram, а не альтернатива ему.**
Дистрибутив `kurigram 2.2.25` ставит тот же импортируемый неймспейс `pyrogram`:

```
import pyrogram                          -> 2.2.25  (site-packages/pyrogram/__init__.py)
from pyrogram import Client, filters     -> OK
from pyrogram.enums import ParseMode     -> OK
from pyrogram.types import Message       -> OK
```

То есть `bot/main.py:18` со своим `from pyrogram import ...` корректен, а чистая
установка по `requirements.txt` бота **не ломает** — вопреки тому, что здесь
утверждалось. Формулировка «в системе установлен pyrogram, kurigram — нет» была
неверна: установлен именно kurigram, а pyrogram как отдельный дистрибутив отсутствует.
Оригинальный pyrogram не собирается под Python 3.13+, отсюда выбор форка.

В `requirements.txt` добавлен комментарий-предупреждение, чтобы это не «починили»
обратно, и дописан `pytest` — тесты раньше не были объявлены вовсе.
