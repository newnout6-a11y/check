# АРХИТЕКТУРА PUSTO — полный разбор кода

> Детальная карта репозитория по состоянию на 2026-08-30. Читалось всё: 16 корневых модулей,
> `bot/` целиком, `gate_client.py` (1609 строк), `docs/` (8 файлов), выборочно — `research/`,
> `archive/` (198 файлов), `scratch/`, `tests/`, `data/`. Цифры состояния пула проверены
> прямыми запросами к SQLite/JSON, не взяты из документов.

---

## 1. Короткий вердикт

Это **не набор скриптов, а законченная фабрика**: добыча доноров → квалификация поверхности →
боевой чек карты → выдача вердикта, с телеграм-ботом как фронтендом и кредитной экономикой.
Архитектурно проект крепче, чем выглядит: единый движок (`gate_client.py`) вместо копипасты,
плагинный реестр гейтов, SQLite-очередь вместо txt-файлов, централизованный `config.py`,
61 тест, аккуратная таксономия вердиктов.

Но **боеспособность упирается не в код, а в носители**. Код готов к работе на 6 поверхностях;
реально живы две. Всё остальное — инфраструктура, ожидающая целей.

**Ключевое архитектурное решение:** `gate_client.py` — единственный источник правды для
всех HTTP-механик. Правка вёрстки WooCommerce чинится в одном месте, а не в пяти скриптах.
Это правильно и это главная причина, по которой проект до сих пор собран.

### 4.2 Что внутри `store_api_confirm` — самая ценная часть движка

Это ~380 строк накопленной боли. Что там сделано и почему:

| Механика | Строки | Суть |
|---|---|---|
| **`_take_nonce`** | 1206–1216 | Nonce одноразовый на мутацию — каждый ответ несёт свежий. Хелпер забирает его из заголовка `Nonce`, 7 точек вызова. До осознания этого все мутации после первой падали. |
| **Гео-выравнивание** | 1253 | GET /checkout возвращает страну магазина — биллинг перестраивается под неё. До этого BIN-card/US-address давал ложные fraud-отказы. |
| **Enum-ретрай payment_method** | 1340–1400 | Из локализованной ошибки (`Zahlungsarten-Typ ungültig`) выдирается полный список методов, перебираются только card-plausible, wallet-методы в чёрном списке. |
| **ISO-3166-2 / short-state ретрай** | 1300–1330 | NL/DE/ES/LT требуют короткий код провинции; ошибка парсится, формат меняется, repeat. |
| **`address_2`-ретрай** | ~1310 | Часть магазинов требует вторую строку адреса. |
| **shipping-rate через update-customer** | 1271+ | Выбор способа доставки отдельной мутацией до платежа. |
| **Парс client_secret из base64-редиректа** | ~1400 | Woo прячет секрет в base64 в Location — выдирается. |
| **PI_PENDING вместо APPROVED@PAID** | 1437–1443, 1450–1456 | `success:true` без живого `succeeded` в PI = заказ оформлен, банк не тронут. Раньше давало фантомные APPROVED. |

Этот модуль — главный инженерный актив проекта. Он пережил 4 раунда багфиксов (BUG-12/13/14, R-1…R-6) и сейчас честно различает «заказ создан» и «деньги списаны».

## 6. Таксономия вердиктов (`config.py`)

23 класса. Ценная часть — не список, а **семантика**:

```
incorrect_cvc        → APPROVED@CCN   (карта жива, PAN/exp валидны)
insufficient_funds   → APPROVED@CVV   (карта жива, CVV валиден)
stolen_card/lost     → DECLINED@STOLEN
do_not_honor/generic → DECLINED@DO_NOT_HONOR
transStatus Y        → 3DS_FRICTIONLESS → (poll) APPROVED@PAID
transStatus C        → 3DS_CHALLENGE   ← это ВЕРДИКТ "жива и enrolled", не провал
transStatus N/R      → DECLINED
PI succeeded         → APPROVED@PAID
PI processing        → PI_PENDING      ← честное "не знаем"
```

`HIT_VERDICTS = {APPROVED, APPROVED@HOLD, APPROVED@CVV, APPROVED@CCN}` в корневом `config.py`;
бот расширяет его `APPROVED@PAID`, `3DS_FRICTIONLESS`, `3DS_CHALLENGE` (`bot/main.py:38`).

Разделение `APPROVED@CVV` / `APPROVED@CCN` — это то, что отличает чекер от «бинарного валидатора»:
оно говорит *какая часть* карты верна. Рыночная ценность именно здесь.

## 7. Бот (`bot/`)

### 7.1 Устройство

- **Pyrogram** (kurigram — живой форк под новые Python), polling, `app.run()`.
- **Реестр гейтов** (`bot/gates/__init__.py:12`): автодискавери по пакету, контракт `async gate(cc,mm,yy,cvv) -> tuple`. Модуль с ошибкой импорта не валит бота — выпадает из реестра с логом. Хорошо.
- **Экономика**: `START_CREDITS=5`, `spend_credit` **атомарный** (`UPDATE ... WHERE credits >= ?` + rowcount — lost-update фикс), `refund_credit` при `verdict == ERROR`, ключи `/genkey` → `/redeem`, премиум по дням.
- **Антиспам**: 3 с на команду, в каждой точке входа.
- **Гарды**: `user_only` (from_user=None в каналах), `admin_only`, `html.escape` везде в выводе.
- **`/mass`**: `Semaphore(5) + gather + stop_evt`, до 20 карт. Было 160 с последовательно → ~25 с.
- **Взвешенная ротация**: `_pick_target` по измеренной латентности (1/lat), неизвестные цели получают медианный вес — новые цели тоже исследуются, а не игнорируются.

### 7.2 Команды

`/start /me /redeem /au /st /sp /pi /vbv /b3 /hit /mass /bin /gates /stats /proxy /addproxy /clearproxy`
Админ: `/addcredits /addpremium /genkey`

## 10. Дефекты — приоритизированно

> **Обновление 2026-08-30, раунд 7.** D-1, D-2, D-3, D-8 и D-9 **исправлены**; подробности

### D-1 · P0 · 20 живых Shopify-магазинов выключены из ротации флагом-сиротой — **ИСПРАВЛЕНО**

`shopify_gates.json`: 20 записей имеют **одновременно** `verified: true` и `needs_live_check: true`
(верификация 6.3 прошла, флаг «нужна проверка» никто не снял).
`bot/gates/shopify.py:69` `_unchecked_domains()` отсекает **все** `needs_live_check` без проверки `verified`.

```
72 записи → фильтр dead/blocked → 63 → фильтр needs_live_check → 43 в ротации
```

**Потеря:** 20 боеспособных магазинов, включая весь дешёвый фронт тира 1.
**Фикс:** в `scratch/_verify_shopify_pool.py:32` снимать `needs_live_check` при успешной верификации
(`g.pop("needs_live_check", None)`), либо в `_unchecked_domains()` добавить `and not g.get("verified")`.

### D-2 · P0 · BIN-кэш не работает вообще — **ИСПРАВЛЕНО**

`bin_cache.init_db()` вызывается **только в тестах**. Всё остальное — `get()`/`put()`, которые
глушат любые исключения (`bin_cache.py:47`, `:58`). Таблицы `bins` нет → `data/bin_cache.db` 0 байт →
`cached_lookup` всегда идёт в сеть, `put` всегда молча падает.

**Последствия:** фикс A1 из раунда скорости мёртв; на каждый новый BIN бот тратит 1.5–18 с
(3 источника × 6 с), первый чек BIN'а идёт с US-гео вместо страны эмитента.
**Фикс:** одна строка — `bin_cache.init_db()` при старте бота (или ленивая инициализация в `_db()`).

### D-3 · P1 · `/chk` не существует — **ИСПРАВЛЕНО**

`bot/main.py:68` `GATE_ALIASES` = `au/st/sh/sp/pi/vbv/b3`. Команды `chk` нет ни в алиасах,
